# Proposed native target execution gates

Current evidence is author-executed Rust 1.96.0 on aarch64 macOS. Existing CI's verify (3.11)/(3.12), lint, instance-data and SAST jobs do not compile or execute Rust. Green Python jobs never certify Linux or Windows native behavior. No new runner/workflow or host access is introduced by this proposal.

The current public workflow runs only ubuntu-latest. A future reviewed change could place one pinned, jobs=1, locked/offline-after-registry-fetch Rust gate in the existing verify (3.12) job, preserving both required Python status names and their checks. This reuses a job but increases its work; runner-minute/cache/storage eligibility and limits must be confirmed before enabling. Cache only Cargo registry/build artifacts, keyed by OS/architecture/toolchain/lock; never credential files or archives. Official dependency/toolchain fetch only, no live provider invocation. Keep normal HTTP safety and JSON policy counts separate.

That proposal provides Linux execution only. Windows requires a Windows runner or separately authorized machine; macOS can retain the current authorized local gate. Adding Windows/macOS hosted jobs may change quotas/cost and needs a concrete approved budget. The five other personal hosts currently lack authorization, so they cannot supply evidence. Cross-compilation alone is not an execution gate. Until authorized execution exists, leave the target row pending rather than mark the migration complete.

For each actual target record exact source SHA, Rust/MSRV/lock SHA, target triple, compiler/SQLite build prerequisites, Python oracle version, process/proxy/TLS/certificate setup and executed/failed/skipped cases. Execute native tests; reference CLI JSON/text/exit/Unicode paths; feed/FTS/WAL/copy/dry-run/idempotence/interruption/rollback; localhost TLS/proxy/header/no-retry/global-time safety; provider request/fallback tests; native subprocess timeout/output bounds; signal/broken-pipe and MCP framing. Use synthetic temp data and process-local CA trust only. Windows symlink/WAL/file-lock and PowerShell/MSYS paths need explicit measured cases; unsupported/permission-dependent skips remain blockers. Preserve locked fixture data and distinguish Python-version-dependent malformed behavior from approved native safety decisions.

This is a proposal, not executed three-OS CI or permission to install tools, add billed runners, alter protection, replace the installed CLI, or switch real archives. Exact target evidence, packaging/notices and all pending matrix rows remain final acceptance gates.
