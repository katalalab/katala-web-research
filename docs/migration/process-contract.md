# Native subprocess preview contract

GitHub repository search uses the original gh argument vector and 30-second timeout. OpenAlex op resolution is a later consumer with the reference ten-second timeout; no real gh/op, authentication store or vault was accessed during development. Runtime is native Rust, with Python only as the offline reference. Arguments and output never enter process error diagnostics. Availability and execution are separate, so executable disappearance/permission failure propagates instead of silently invoking REST. Timeout, nonzero status and empty normalized gh results invoke the original single REST fallback; malformed gh JSON/UTF-8 does not. All-retracted gh results remain an empty ranked result without REST fallback.

The Unix runner creates an owned process group, captures both streams concurrently, reaps the child and kills the owned group on exit/error/deadline. Deadline starts before spawn and covers stream draining, including descendants holding pipes. The synchronous OS spawn/path/image-loading phase cannot be forcibly cancelled; elapsed time is checked afterward. No shell or provider retry is used. Source stdin is null rather than interactive. A shared eight-MiB stdout+stderr cap returns OutputLimitError and cleans up the owned group. Empty stdin and this cap are explicit safety differences from unbounded inherited Python subprocess I/O, pending final contract acceptance.

During active runs a reference-counted SIGINT/SIGTERM scope records signals using a lock-free atomic. It restores previous actions when the last run finishes; each interrupted run cleans up its owned group. Library errors are KeyboardInterrupt or SignalError. Full CLI signal exit-code/output parity, ignored/custom disposition behavior, concurrent signal stress, SIGKILL/power loss, detached descendants escaping their group and OS PID-reuse edge cases remain acceptance gates. Never infer hard-kill cleanup from graceful-signal tests.

Native execution currently exists on Unix only. Non-Unix run returns NotImplementedError without spawning. Windows executable lookup/PATHEXT, Job Object descendant ownership, pipe cancellation and execution remain blockers; no Windows/Linux native execution has been claimed. Pure provider transcript tests are portable evidence, not target execution. Linux/macOS PID/signal/session assumptions still require their actual target gate.

Author aarch64 macOS evidence: five raw process comparisons (argv metacharacters passed literally, UTF-8, CRLF, raw invalid bytes, exact cap and Unicode/space executable path), eight policy assertions (missing executable, stdout/stderr/combined caps, deadline, owned descendant heartbeat stops, SIGINT and SIGTERM descendant cleanup). The executable is built from rust/tests/support/process_fixture.rs; never an installed gh/op or unknown helper. The 51 strict GitHub repository adapter cases record availability/run arguments/timeouts, fallback/error/request/normalization/metadata/rank ordering; 30 paired localhost CLI comparisons use this executable named gh in an isolated PATH and exact api.github.com-to-loopback TLS proxy mapping. Each CLI archive asserts all eight synthetic user tables populated before full dump/version/integrity comparison. No arbitrary archive, real credential, live API or global OS trust/network setting is involved.
