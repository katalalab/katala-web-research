# Provider boundary and offline adapter

Eight network surfaces share native request/response/error/result types: ddg, github, github_code, jina, searxng, brave, openalex, meta. DDG, SearXNG, Brave and Jina normal fields are now native; github, github_code, openalex and meta remain pending. Feed remains the implemented local provider. A mutable transport receives an exact GET request URL plus canonical headers, returns raw HttpResponse, or a typed redacted failure. An offline adapter must match requests in order, return scripted synthetic responses/failures, reject unexpected calls, and assert all scripted steps were consumed. It never falls through to network. Provider implementations normalize responses to the existing SearchResult fields, preserve provider rank metadata, then use the existing rank pipeline. CLI query rewriting/candidate/category/highlight and slicing remain outside transport.

HTTP safety changes and remaining charset/URL/proxy edges are inherited from PR #20 head 5da9fc8, now merged as main 96519c1 after parent's independent review and authorization. DNS/native trust initialization have no guaranteed full wallclock cancellation; authenticated proxy, unusual codecs, OS and live provider gates remain unverified. HTTP/2 and HTTP/3 are disabled in current reqwest features. If either is enabled later, explicitly disable and fixture-check protocol retries before preserving the zero-retry contract. Credentials remain in explicitly supplied environment/config at runtime; test adapters use public synthetic markers only. Provider errors never contain body previews or arbitrary subprocess diagnostics. Four remaining providers remain unsupported until their native vertical behavior and matrix gates pass; the shared trait does not certify them.

Current native DDG evidence: 14 Python-derived parser cases and 84 search request/rank cases; strict adapter rejects unscripted/mismatched calls, remembers mismatches even if an error were caught, rejects unused steps, and preserves scripted error kinds without retries. 24 localhost CLI comparisons cover default/explicit provider, UTF-8 query encoding, categories/domain filters/candidate/signed limits, cached highlights, unchanged archive pages, empty/status/timeout behavior. No extra production fixture URL option or Python wrapper is introduced. The small streaming HTML parser covers normal fields and tested nested tags/entities/raw script/style; malformed/partial HTML, exotic attribute syntax and full transport edges still need reference cases before complete DDG parity.

## Slice 5: normal JSON providers

Native SearXNG uses the existing instance URL and optional categories, engines, language, time range and safesearch. It requests JSON with q first; pageno starts at 2, with 20 results per page and ceil(requested/20) pages as Python does. It requires the instance even for zero, then returns before optional validation when requested <=0. It stops on empty results or the requested raw count. There is no new arbitrary page cap; callers must choose bounded candidate counts until a separately reviewed safety change.

Brave requires its existing key, returns before optional validation for requested <=0, requests count=20 and offset from 1 on subsequent pages, caps at ten pages, and preserves country/search/UI language, freshness aliases/date-range structure and safesearch. Freshness preserves the reference's uppercase abbreviated rejection and structural, non-calendar date validation. Jina requires its existing key, uses Bearer auth and the unchanged search URL, fetches once even for zero/negative library limits, applies Python signed list slicing before rank, and preserves description/content and publishedTime/published_at fallback. No paid/live request is part of these gates.

Each uses the strict shared transport, response normalization and common rank pipeline; CLI retains query/category/candidate filters, cached highlights, and both slices. Config values have no Debug formatter. Credential values appear only in explicit runtime headers; native errors omit body previews and HTTP URL credentials. Later-page failures abort the result rather than return partial success, with no automatic retry. The CLI compares process status, JSON/text fields and request order/header values to Python. Synthetic fixtures assert the full existing database schema/row dump, user_version and integrity remain unchanged.

Evidence: 83 Python-derived adapter cases (SearXNG 31, Brave 33, Jina 19), plus 76 localhost CLI comparisons (27/27/22). Required/malformed config rejects before requests; empty/missing/nullable fields, rank/dedup/retraction, Unicode URL encoding, paging/empty-page/ten-page cap, HTTP/timeout/non-JSON/later-page failure and redaction are covered per provider. The CONNECT proxy forwards only the exact Brave/Jina fixture names to loopback, rejecting all other targets; the CA is temporary and process-local. Neither fixture can fall through to a provider.

Final acceptance remains pending: Python-version-dependent Unicode/schema acceptance beyond the recorded oracle and explicit policy acceptance, unusual URLs/charsets/authenticated proxies, resolver cancellation, OS and all live providers. Doctor preflight remains an unimplemented command. Header-invalid credential bytes and missing-config versus invalid HTTP-setting precedence need edge fixtures. The same preserved safety differences from http-contract.md apply. No normal-field checkpoint implies full provider or complete migration parity.


PR #22 P1 redirects: Brave's X-Subscription-Token is now covered by the common case-insensitive cross-origin safe-header allowlist, alongside conventional and unknown secret names. Same-origin behavior is retained; crossing host or effective port permanently removes caller credential headers for that request chain. The four synthetic Brave redirect policy comparisons intentionally differ from Python's marker-forwarding behavior. See http-contract.md for the exact allowlist and reproduction evidence. This repair adds no next-provider or malformed-JSON feature to the reviewed PR.


## Slice 6: JSON edges and config ordering

The next independent slice follows approved main fc8db85 (PR #22 repaired head 23369e8). Additional Python 3.13 / Unicode 15.1 oracles cover 259 library cases, separately SearXNG 90, Brave 86, Jina 83. Categories include every root scalar/null/array, missing or wrongly typed collections/items, false/null/empty/string/number/array/object result fields, truncated/trailing/BOM/duplicate-key/control JSON, NaN/Infinity, unpaired surrogate strings, deep nesting, UTF-8/IDN/control queries, empty/whitespace credentials, Unicode safesearch/freshness/year fields.

Unicode decimal digits are now converted using frozen facts from the local Python oracle; Arabic/fullwidth/mathematical decimal config and four-character publication years match the reference. isdigit-only superscripts still produce the reference ValueError when an integer conversion is needed; Brave structural date validation retains isdigit acceptance. No new runtime dependency or Python call is introduced. HTTP environment settings are initialized only on the first actual transport call, after provider preflight, so missing keys and invalid optional settings are not masked by an invalid HTTP timeout.

The fixture contains exact Python outcomes plus separately named native expectations for 55 deliberate differences; no unexpected mismatch is normalized. typed_fields rejects unsupported model/date types without echoing values instead of allowing Python's later urllib/regex failure or ill-typed publication output. typed_collections rejects Jina dict data as TypeError rather than version-dependent dict-slice KeyError/TypeError. strict_json_constants rejects nonstandard NaN/Infinity; strict_unicode rejects unpaired surrogates; depth_limit retains serde_json bounded nesting. These explicit safety decisions still require final acceptance; they do not close a provider row.

CLI evidence: 255 library-derived cases through localhost plus eight paired config/credential boundaries = 263 paired comparisons (92/87/84), including all 55 named policy comparisons; one additional native-only userinfo rejection, nine config boundaries total. The three NUL-query cases stay library-only because native OS argv cannot carry NUL. Whitespace-only SearXNG endpoint is measured as a real transport rejection rather than the mocked-library success. Header CRLF is rejected before any socket request; wrong local path 404, malformed/whitespace endpoint, missing key before invalid HTTP settings and synthetic userinfo rejection are covered. Python userinfo resolution is deliberately never attempted. Every child preserves the full old synthetic DB schema/row dump, version and integrity. No provider/DNS/paid call, real key, OS trust or archive switch.

Oracle replay requires the recorded Python 3.13 Unicode version: generate_json_provider_edges.py and generate_python_digits.py, then pinned scripts/rust.sh fmt. Native tests and committed fixtures require no generator or Python runtime. Python 3.11/3.12 CI remains the unchanged reference verifier; it is not evidence that all malformed-JSON outcomes or Unicode tables are identical across Python versions. Remaining codec/URL/env byte/schema/version/auth proxy, resolver/signal/OS/live edges and four other providers remain open.
